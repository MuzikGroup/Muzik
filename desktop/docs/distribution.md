# Distribution packaging

## What releases ship

Every stable release from `MuzikGroup/Muzik` publishes, in one release:

- **Windows**: `Muzik-VERSION-windows-x64.msi` plus a portable ZIP
- **macOS**: `Muzik-VERSION-macos-arm64.dmg` (Apple Silicon) — Intel Macs use the portable JAR with Java 21+
- **Linux**: `muzik-VERSION-linux-amd64.deb`, `muzik-VERSION-linux-x64.rpm`, and the portable JAR
- **Any OS with Java 21+**: `muzik-VERSION-portable.jar` (architecture-independent)
- `SHA256SUMS` covering every asset, generated by `release.yml` at publication time

The asset names above are the contract the packaging tooling below relies on; keep them stable.

## Generate recipes

Recipes are rendered manually from a stable release — the asset names and checksums come from the published release, never a latest-version placeholder. Run locally with an authenticated GitHub CLI and an existing stable `tag`:

```sh
mkdir -p build
gh release view "$tag" --repo MuzikGroup/Muzik \
  --json tagName,isDraft,isPrerelease,url,publishedAt,body,assets > build/release.json
gh release download "$tag" --repo MuzikGroup/Muzik \
  --dir build/distribution-assets --pattern SHA256SUMS \
  --pattern 'Muzik-*-windows-x64.msi' \
  --pattern 'Muzik-*-macos-arm64.dmg' \
  --pattern 'muzik-*-portable.jar'
python3 scripts/generate_distribution.py \
  --assets build/distribution-assets --release build/release.json \
  --output build/distribution
```

The generator verifies every asset against `SHA256SUMS` before rendering anything. See [release packages](install/README.md#get-the-package) for filenames.

## WinGet

`packaging/winget/` renders version, locale and installer manifests under `manifests/m/MuzikGroup/Muzik/VERSION/`. The installer manifest points at the release-bound MSI; WinGet drives `msiexec` for silent installs and upgrades.

Run `winget validate --manifest PATH` on Windows, then test clean install, upgrade and uninstall before submission. Do not request elevation or purge user data.

## Homebrew

`packaging/homebrew/muzik.rb.in` is the generator's cask template: the Apple Silicon DMG, a GitHub-latest livecheck and a homepage at `MuzikGroup/Muzik`. Publishing a tap is manual — render the cask with the generator and submit it to a `MuzikGroup/homebrew-tap` repository when one exists. Intel Macs are served by the portable JAR, not the cask.

Run `brew style --cask PATH` before submitting, and follow [unsigned-app installation](install/macos.md#install-and-verify) on Gatekeeper.

## Nix

`flake.nix` builds the portable JAR with OpenJDK 21 for Linux x86_64/aarch64 and pins nixpkgs. `packaging/nix/package.nix` wraps the JAR with the GTK, WebKitGTK, Secret Service, D-Bus and `glib-networking` runtime libraries, and adds `glib-networking`'s GIO modules to `GIO_EXTRA_MODULES` for WebKitGTK TLS.

Do not add `alsa-plugins` to the runtime libraries: its `/etc/alsa` would hide the host's PipeWire configuration.

```sh
nix build path:./build/distribution/nix
nix run path:./build/distribution/nix
```

The root flake reads the committed `packaging/release.json`, so `nix run github:MuzikGroup/Muzik` installs the latest stable release. After each stable release, regenerate the distribution and copy the generated `nix/packaging/release.json` to `packaging/release.json`, then commit it. Missing metadata fails with generation instructions rather than a fake hash. Verify login, Secret Service, audio and playback on both architectures.

Local AppImage packaging (`make build-appimage`, backed by `scripts/build_appimage.sh` and `scripts/linux-appimage-apprun.sh`) remains available for development, but releases ship the DEB/RPM/JAR set — no AppImage.

## Optional external proposals

Generation needs no extra secret. External proposals need `PACKAGING_PR_TOKEN` plus the destination repository variable as `owner/repo`:

| Variable | Destination |
| --- | --- |
| `WINGET_REPOSITORY` | WinGet staging repository or fork |
| `HOMEBREW_REPOSITORY` | Homebrew tap |
| `NIX_REPOSITORY` | Generated flake |

The token needs Contents/Pull requests write permission and source visibility access. The script refuses writes while the source repository is private.

`scripts/propose_distribution.py` creates or updates `build/muzik-VERSION` and opens a draft PR against the destination's default branch. It never force-pushes or merges. WinGet staging PRs need a separate upstream submission.
